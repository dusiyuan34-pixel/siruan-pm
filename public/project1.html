阶段 0｜需求梳理

WHY0.0 设计五原则（所有功能评审的最高准则）

任何功能要进 v1.0，必须至少满足下面一条；与这五条冲突的，一票否决。

①

漫步感优先

任何需要玩家"刷"的设计都要质疑

②

场景会说话

不写大段对白，叙事靠环境

③

稀缺制造恐惧

敌人少 = 每个敌人都重要

④

失败不惩罚探索欲

死亡不丢线索，不强迫重复劳动

⑤

美术服务于叙事

每栋建筑都要有故事，不是背景板

WHY0.4 目标用户画像

🎯 主用户

18–28 岁，男 65% / 女 35%，Steam 国区玩家，单库游戏时长 200h+，玩过《艾迪芬奇的记忆》《看火人》《最后生还者 第二部》《天国：拯救》并给出好评

⏱ 次用户

28–35 岁时间碎片化玩家，偏好短章节叙事，不追求高强度操作

🚫 反目标用户

追求数值 Build、PVP、每日签到、社交炫耀的玩家 —— 他们不是我们的客群，不要为他们加功能

WHY0.5 产品定位（情绪锚点）

"一个让你愿意停下来拍照的末世城市漫步游戏。"
所有设计决策都拿这句话当尺子：任何破坏"漫步感"的功能都砍。

WHY0.5 PRD 最关键的一段 —— 不做什么

这一段写不出来，后面所有功能讨论都会被范围蔓延拖死。变更流程：任何 Out of Scope 项要进入 v1.0，必须提交一页纸提案 + 制作人/主程/主美三方投票，任一方反对则顺延。

  • ❌ 不做联机 / 多人 / 合作
  • ❌ 不做角色捏脸、Build、技能树
  • ❌ 不做内购、皮肤、通行证
  • ❌ 不做硬核生存（饥饿 / 口渴 / 体温 / 睡眠全砍）
  • ❌ 不做昼夜循环、动态天气（只做固定天气演出）
  • ❌ 不做开放世界大地图，做 5 个手工打磨的章节区块
  • ❌ 移动端首发（PC 优先，移动端不做）

WHY0.6 In Scope（v1.0 明确要做什么）

  • ✅ 5 个手工打磨章节区块
  • ✅ 6 大系统：探索 / 残响叙事 / 生存 / 解谜 / 遭遇战 / 据点
  • ✅ 3 个据点（中转站公寓 / 地铁站掩体 / 天文台）
  • ✅ 真结局 + 假结局（60/80 残响触发）
  • ✅ 简中 / 英文首发；日文发售 3 个月后补丁
  • ✅ 20 个 Steam 成就

WHY0.7 竞品深度拆解（Steam 真实数据 + 差异化定位）

3.1

《遗迹：灰烬重生》Remnant: From the Ashes

Steam 数据：75% 特别好评 / 定价 ¥120 / 首周 10w+（Gunfire 公开数据）

优点：Boss 战设计扎实；程序化地图重玩性

缺点（我们要利用）：美术资产成本极高 → 区域重复感强；联机强制感，单人体验割裂；叙事碎片化到玩家不理解

→ 我们差异化：手工关卡 + 强叙事 + 单人沉浸

3.2

《明日之后》

数据：上线首月流水 20 亿，1 年内 DAU 掉 80%（公开财报/第三方监测）

优点：生存资源循环（采集→制造→防御）被验证可行

缺点：每日任务 + 体力 = 上班感；PVP 逼氪；末世氛围被聊天频道稀释

→ 我们差异化：单机买断，零干扰

3.3

《幽灵线：东京》

Steam 数据：60% 褒贬不一 / 定价 ¥195 / SteamDB 显示发行后口碑快速下滑

优点：都市废墟氛围感天花板，第一人称沉浸强

缺点：开放世界但内容空洞，跑腿任务占 70%；战斗系统单调；地图与叙事弱关联

→ 我们差异化：手工章节 + 解谜驱动 + 战斗稀缺

WHAT1.2 六大系统 PRD 三件套（入口 / 规则 / 边界 case）

A

探索系统

规则：步行 2.5 m/s，奔跑 4.5 m/s（体力条 10s / 回复 5s）；勘测器 被动：距离可互动物 < 5m 时屏幕右下角轻微脉冲；主动：Q 键勘测视角，15m 内高亮 2s，冷却 30s；导航：据点地图标位置，野外 不显示方向箭头

⚠ 边界：卡墙 3s → 自动回弹；掉出地图 → 回锚点；5 分钟无操作 → 待机镜头（拍照模式）

B

场景叙事系统（残响）

规则：全游戏 80 个残响（视觉 40% / 听觉 30% / 文本 30%）；收集 60 → 假结局；80 → 真结局；三条叙事线并行：灾变原因 / 主角身世 / 城市陷落时间线

⚠ 边界：阅读时游戏时间暂停；移动端字号 ≥ 16sp 支持双指缩放；据点设"残响回顾"菜单

C

轻度生存系统

只保留三件套：① 背包容量（基础 20 格，据点升级 +10/次，最多 30 格）② 装备耐久（撬棍 30 次 / 手电 120min / 防毒面具 60min）③ 环境伤害（酸雨 -2/s / 坍塌 -5/s）

死亡惩罚：回锚点，不掉线索，只丢一半材料；装备耐久归 0 → 断裂可修，不是销毁

D

空间解谜系统

原则：谜题必须是"看懂这栋楼"，不是"找对按钮"。全游戏 17 个谜题：结构路径 6 / 重量平衡 3 / 电源恢复 4 / 环境观察 4

三档提示状态机：卡 5min → 环境暗示句；10min → 白色轮廓指引（只标方向）；15min → 直接高亮

⚠ 验收：17 个谜题外部 10 人测试，平均解出时间 5-10 min；提示使用率 5min ≤ 60% / 10min ≤ 30% / 15min ≤ 10%

E

遭遇战系统

原则：敌人是"事件"，不是"杂兵"。共 5 种敌人（游荡者 / 变异犬 / 巢穴孢子 / 拾荒者 / 章 Boss）；每章遭遇点 < 6 个，不刷怪

战斗三选一：暗杀（背刺一击必杀）/ 逃跑（脱战回原位）/ 正面（胜率 < 50%，故意的）

⚠ 据点内绝无敌人；战斗中存档在战后触发；怪的寻路每 5s 重置

F

据点系统

3 个据点：中转站公寓（Ch1 末 / 基础）→ 地铁站掩体（Ch3 末 / + 仓库 + 残响回顾）→ 天文台（Ch5 前 / + 结局分支）；据点绝对安全

存档：1 autosave + 1 手动槽；离开据点前自动存档

🌧️ 野外

冷色、低饱和、环境音留白；HUD 极简（HP 条 + 装备耐久 < 30% 才显示）

💡 产品思考：体验侧 vs 生产侧，PM 两边都要管

PM 不仅要写 PRD，还要能 画节奏曲线（关卡验收标准）、算预算回本线（立项可行性）、盯数据埋点（上线后验证假设）。这三件事，纯美术或纯程序背景的候选人通常不会主动做。

HOW2.3 美术资产成本方案（PM × 美术协同）

这是 PM 懂美术管线的核心价值：不等美术报完成本再砍需求，而是从一开始就提可落地的成本方案。

🏗️ 模块化建筑

底座 ×3 + 中段 ×4 + 屋顶 ×3 = 36 种外观组合，覆盖全部 5 章的城市建筑

🎨 PBR 材质球库

混凝土 ×3 / 铁锈 ×2 / 植被 ×3 / 破损 ×2，跨模型共用，不每个建筑单独做材质

⚡ 程序化点缀

墙面涂鸦、地面杂物用 Substance Designer + 引擎 Procedural Scatter 生成，不手工摆放

🎯 目标

单章节美术资产产出从 6 人周压到 3 人周，直接砍掉一半美术成本
